Цель: мотивировать участников фестиваля проявлять социальную активность в сообществе анонсов во вконтакте @kldevents

Задача: Мониторить лайки, комментарии и репосты как инструмент повышающий количество баллов и вероятность выиграть в билеты в розыгрышах на спецмероприятия

Идея контролировать максимально автоматизировано

Я даю вк-юзер-токен в env для доступов, пользователь является владельцем сообщества

Варианты связки событий социальной активности и участников:
1. матчинг с ФИО в заявителях на розыгрыш на спецмероприятие
2. авторизация через Вк и получение Вк id
3. подключение авторизации через Вк для записи на события фестиваля

Потребуется реализовать авторизацию через Вк, для этого нужно будет настроить поддомен api.kgd80.ru. — Статус: `Настроено на production, не подтверждено пользователем`

## Качество распознавания штампов в заявках на розыгрыш

Already present:
- Заявки на спецмероприятия уже используют фото паспорта участника и распознанное количество штампов как один из факторов допуска и веса в розыгрыше. — Статус: `Зафиксировано`

Needs clarification:
- Production-инцидент от `2026-06-15`: ручная сверка показала, что неверное определение количества штампов является массовым явлением, а не единичной ошибкой отдельной заявки. OCR/LLM-подсчёт нельзя считать достаточным источником истины без операторской проверки спорных случаев. — Статус: `Не выполнено`
- Для заявок на розыгрыш нужен явный операторский сценарий ручной корректировки количества штампов с пересчётом баллов, неявок и веса в розыгрыше до публикации результатов. — Статус: `Не выполнено`

Missing:
- Нужен аудит качества распознавания штампов по уже поданным production-заявкам до проведения следующих розыгрышей: список заявок, исходное OCR-значение, ручное значение, итоговый пересчёт баллов и дата/основание корректировки. — Статус: `Не выполнено`
- Нужен технический журнал ручных корректировок штампов, чтобы production-правки не оставались только прямым изменением SQLite-строк. — Статус: `Не выполнено`

## VK social monitoring v1 для спецзаявок

Already present:
- Источник VK user-token владельца/админа сообщества уже зафиксирован как env-доступ для автоматизированного контроля активности. — Статус: `Зафиксировано`
- Матчинг социальной активности с ФИО заявителей на розыгрыш уже зафиксирован как один из допустимых вариантов связки. — Статус: `Зафиксировано`

Needs clarification:
- v1 мониторит только production-заявки на спецмероприятия, а не все обычные регистрации фестиваля. На момент read-only проверки production-объём v1: `83` спецзаявки. — Статус: `Реализовано в коде, не подтверждено пользователем`
- v1 не меняет `score`, веса розыгрыша или доступность заявок; результатом является отчёт для оператора. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Источник v1 гибридный: `notifications.get` для свежих уведомлений и wall backfill по последним постам двух VK-групп: `klgdevents` (`231920894`) и `kenigeventsofficial` (`231828790`). — Статус: `Реализовано в коде, не подтверждено пользователем`
- Расписание production job: два запуска в день, в `09:00` и `21:00` по `Europe/Kaliningrad`; повторный запуск в том же окне не должен создавать второй run. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Все VK API вызовы должны идти через локальный rate-limit wrapper с паузой около `1100ms` и retry/backoff на VK `error_code=6`. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Отчёт должен разделять `matched`, `weak`, `ambiguous`, `unmatched`, показывать counts активностей, confidence, метод и reason, без массового вывода расшифрованных ФИО в логах. — Статус: `Реализовано в коде, не подтверждено пользователем`
- LLM fallback допускается только после детерминистики для `weak`/`ambiguous` кандидатов, батчами и только через существующий `runLlmLimited`; прямые LLM-запросы вне limiter запрещены. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Результаты LLM/детерминистики должны кэшироваться по `vk_user_id` и snapshot display-name, чтобы не сверять одного VK-пользователя повторно без изменения имени. — Статус: `Реализовано в коде, не подтверждено пользователем`

Missing:
- Перед включением на production нужно добавить/проверить Fly secrets/env: `VK_AUTH_TOKEN`, `PII_PRIVATE_KEY_PEM_B64`, при включённом LLM — `FOUR_O_URL`/`SOCIAL_MATCH_LLM_URL`, `FOUR_O_TOKEN`, `SOCIAL_MATCH_LLM_MODEL`. — Статус: `Не выполнено`
- После первого production run нужно вручную проверить отчёт `GET /api/v1/admin/social/vk/report` и подтвердить качество матчей на edge cases: переставленные имя/фамилия, имя+отчество, дубликаты имён, organization-like аккаунты, закрытые профили. — Статус: `Не выполнено`
