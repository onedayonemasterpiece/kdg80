## VK social scoring v2 для автоматического розыгрыша

Already present:
- Автоматический розыгрыш реализован в `registration/src/services/special-draws.ts`: кандидаты берутся из `special_applications` со статусом `accepted` и положительным паспортным `score`; победитель выбирается weighted-draw без возвращения. — Статус: `Зафиксировано`
- Текущая паспортная модель находится в `registration/src/services/special-applications.ts`: минимум `min_stamp_count=5` штампов даёт `base_points=10`, каждый дополнительный штамп даёт `extra_stamp_points=2`, неявки сверх grace уменьшают паспортные баллы. Это не модель «1 штамп = 10 баллов»: 10 — базовый вес допуска после минимального порога. — Статус: `Зафиксировано`
- Повторная победа внутри того же спецмероприятия запрещена: участник, уже выигравший другой показ того же `special_event`, исключается из кандидатов. Победа в другом спецмероприятии допускается, но применяется `previous_winner_weight_percent` к паспортной части веса. — Статус: `Зафиксировано`

Needs clarification:
- Социальная активность не должна открывать доступ в розыгрыш без достаточных штампов: базовый фильтр `accepted` + `score > 0` остаётся паспортным. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Соцбонус считается только для VK-профилей с `match_status=matched` и confidence не ниже `0.85`; `weak`, `ambiguous` и `unmatched` не получают автоматические баллы, чтобы не начислять чужую активность. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Калибровка справедливости: один дополнительный штамп после минимального порога равен `extra_stamp_points=2`; два «очень хороших» социальных дня дают примерно те же `2` балла. Один хороший день: минимум `1` репост и `2` комментария = около `1.1` сырого соцбалла. Соцбаллы считаются за весь накопленный период в `vk_social_activities`, без среза 24 часа. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Вес действий по влиянию на VK: репост сильнее всего (`0.6` дневного балла), комментарий/ответ (`0.25`), лайк поста/видео (`0.15`), лайк комментария (`0.05`). Дневные cap-и защищают от спама: репосты до `1.0`, комментарии до `0.5`, лайки постов/видео до `0.5`, лайки комментариев до `0.1`, общий дневной максимум `1.2`. Итоговые соцбаллы остаются честным `floor` от накопленного сырого веса, без персонального округления под отдельного участника. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Итоговый вес показа: `(паспортные_баллы * previous_winner_weight_percent / 100 + соцбонус_без_понижения) / количество_выбранных_дат`. Так победители других спецрозыгрышей получают общее снижение вероятности через паспортную часть, но их новая социальная активность не дисконтируется. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Отчёт о соцактивности должен явно писать, что сообщение создано автоматически, показывать активность по типам и текущий соцбонус, добавленный к розыгрышу. — Статус: `Реализовано в коде для superadmin Telegram-отчёта, не подтверждено пользователем`

- Личные VK-сообщения победителям отправляются только победителям с уверенно определённым VK-получателем. Приоритетный источник — ровно один social-activity match (`matched`, confidence >= `0.85`). Если такого матча нет, допускается fallback по подписчикам двух VK-сообществ `klgdevents` (`231920894`) и `kenigeventsofficial` (`231828790`): точное совпадение `Фамилия Имя` заявки с `last_name first_name` VK-подписчика, после дедупликации одного VK id между двумя группами. Если совпадений нет или найдено несколько разных VK id с тем же именем, отправка пропускается. VK может отклонить доставку, если пользователь не разрешил сообщения сообществу/токену; такие ошибки журналируются. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Для уже опубликованного розыгрыша нужен безопасный повторный запуск только VK-уведомлений без нового выбора победителей. Повторный запуск должен использовать anti-duplicate ledger `special_winner_vk_notifications`: ранее отправленные сообщения не дублируются, failed/pending можно повторить, а новые уверенно найденные получатели получают сообщение. Между попытками личных VK-сообщений нужна пауза по умолчанию около `3` секунд, чтобы не провоцировать VK rate-limit/CAPTCHA при пачке победителей. Telegram-кнопка повторной отправки должна запускать долгую отправку в фоне и присылать итоговый summary отдельным сообщением, не удерживая webhook до завершения всего VK API обхода. — Статус: `Реализовано в коде, не подтверждено пользователем`
- Нужен ledger первой персональной отправки участнику для регулярных отчётов о соцактивности: первая отправка должна показывать всё зафиксированное количество по типам и текущий соцбонус, следующие — дельту. Для сообщений о выигрыше отдельный anti-duplicate ledger реализован через `special_winner_vk_notifications`. — Статус: `Частично реализовано в коде, не подтверждено пользователем`
